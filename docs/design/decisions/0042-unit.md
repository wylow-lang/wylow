# 0042. A `Result` with no success value uses `Unit`

- Status: accepted (2026-11-03)
- Spec: `errors.result`, `structs.unique`

## Decision

`void` stays out of type arguments. `std` declares an empty struct `Unit`, and such a function returns `Result<Unit, E>` with `return Ok(Unit());`. A program imports it; it is not a name every file sees.

## Alternatives

- **`void` as a real type**: Rust's unit type in [`Result<(), E>`](https://doc.rust-lang.org/std/result/index.html). It reads best, but `List<void>` and `var x = log();` become legal, and both executors need the empty case.
- **`void` allowed only in `Result`**: `Result`'s own methods bind `case Ok(var value) -> value`, so each would need a special case.

## Why

It needs no language change, and generic code works unchanged (`basics/unit_result.wyl`). Making `void` a real type later breaks no program.
