# WYL0519

```
error[WYL0519]: nothing that the program links defines 'parser_version', which extern function 'parser_version' names
```

A function or constant of an extern block is provided by C++. A header declares it, and a source file under `native/` or a library that the manifest's `link` list names must define it. If nothing that the program links defines it, the link fails, and the compiler reports the failure at the declaration.

## Example

A package, file by file:

```wylcfg package.wylcfg
name = "parser_tool";
```

```cpp native/parser.h
#pragma once
int parser_version();
```

```wyl src/main.wyl
@Include("parser.h")
extern {
    @Safe int parser_version();
}

void main() {
    std::print(parser_version());
}
```

## Fix

Define the function in a source file under `native/`, or name the library that defines it in the `link` list of the manifest's `native` block.

If a C source under `native/` defines the function, the function has C linkage, and the linker spells its name differently from a C++ function's name. If the header declares the function without `extern "C"`, the program looks for a C++ function, and nothing defines that function. When the package has a C source and the missing name is a C++ name, the error has a note and a help line that say so. Declare the function inside `extern "C"` in the header, and put that block inside `#ifdef __cplusplus` so that the C source can include the same header:

```cpp
#ifdef __cplusplus
extern "C" {
#endif

int parser_version(void);

#ifdef __cplusplus
}
#endif
```
